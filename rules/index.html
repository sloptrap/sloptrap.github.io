WASM Rule Engine & .strule Specification

SlopTrap separates open-source feature extraction and sandboxed execution from signed, encrypted WebAssembly 1.0 rule bundles (.strule) that run identically across servers, desktop CLIs, browser extensions, and embedded runtimes.

1. Architecture overview

  • Zero host imports: Any WASM binary declaring an Import section (secId == 2, WASI, clocks, network, or filesystem calls), Custom section (secId == 0), or implicit Start section (secId == 8) is rejected before execution.
  • Strict memory & CPU bounds: Linear memory must declare an explicit maximum ceiling of at most 32 pages (2 MiB), and evaluations execute under hard per-call deadlines / instruction fuel caps.
  • Declared input cost: Each manifest lists only required feature groups (metadata, upload_cadence, transcript, thumbnails, audio_video_stats) and an overhead rating (1..10) so lightweight clients can run 2/10 metadata rules while servers run full 8/10 ensembles.

3. Guest WebAssembly ABI (wasm-v1)

Modules compiled from Rust (wasm32-unknown-unknown), C/Clang, Zig, TinyGo, AssemblyScript, or SlopTrap's built-in RuleSpec compiler may export only whitelisted symbols:

  • memory — Bounded linear memory (max ≤ 32 pages).
  • st_alloc(size: i32) -> i32 (optional) — Returns byte offset for the input JSON slice (defaults to scratch offset 4096 / 16384 if omitted).
  • st_evaluate(ptr: i32, len: i32) -> i64 (required) — Evaluates memory[ptr .. ptr+len] and returns a packed 64-bit integer:
    • Compact return (upper 32 bits == 0): Lower 32 bits carry the integer score 0..100 (confidence 1.0).
    • JSON slice return (upper 32 bits > 0): (outPtr << 32) | outLen referencing UTF-8 JSON {"score": 88, "confidence": 0.92, "reason": "..."}.

4. .strule envelope & cryptography

{
  "format": "sloptrap-bundle-v1",
  "manifest": {
    "rule_id": "necro-hijack-guard",
    "name": "Necro-Hijack & Dormancy Guard",
    "description": "Detects aged/bought YouTube accounts with multi-year dormancy gaps...",
    "version": "1.2.0",
    "author": "@sloptrap-core",
    "author_public_key": "eb85cbf507e27e2c0f94ad723385db3138af32670ea37ca337f0c1866eae02cc",
    "repo_url": "https://github.com/sloptrap/rule-necro-hijack-guard",
    "interpreter": "wasm-v1",
    "inputs": ["metadata", "upload_cadence", "audio_video_stats"],
    "default_weight": 1.25,
    "overhead": 5,
    "encryption": "aes-256-gcm-hkdf"
  },
  "payload_b64": "<12-byte GCM nonce || AES-256-GCM ciphertext || 16-byte tag>",
  "signature_b64": "<64-byte Ed25519 signature>"
}
  • Canonical Manifest AAD: Newline-delimited canonical manifest bytes serve as AES-256-GCM Additional Authenticated Data (AAD); modifying overhead, inputs, or author_public_key causes decryption failure.
  • RFC 5869 HKDF-SHA256: Derives the 256-bit key using salt sloptrap-hkdf-salt-v1 and info sloptrap-bundle-v1|<rule_id>|<author_pub_hex>|<version>.
  • Ed25519 Signature: Verified over SHA-256("sloptrap-sig-v1:" || canonicalManifest || 0x00 || rawWasmBytes).

5. Automated malicious-content audit & GitHub Action

Every pull request or push modifying .strule bundles or leaderboard.json runs validate-rules.yml (and locally via ./sloptrap rules audit), enforcing four defense layers:

  1. Integrity & authenticity: Enforces ≤ 256 KiB bundle / ≤ 192 KiB WASM ceilings, SHA-256 parity with leaderboard.json, AES-GCM manifest AAD authentication, and Ed25519 signature verification.
  2. Binary section firewall: Parses raw WebAssembly 1.0 sections and rejects Custom sections (id 0, blocking steganographic/smuggled payloads), Import sections (id 2, blocking host/WASI access), Start sections (id 8), unbounded or > 32-page memory, and non-whitelisted exports.
  3. Fuel-metered sandbox fuzzing: Executes probe and malformed JSON payloads under strict instruction fuel / timeout caps to catch infinite-loop CPU bombs and out-of-bounds memory traps, and verifies bit-identical determinism across repeated runs.
  4. Anti-poisoning behavioral guard: Rejects rules that blanket-flag clean human creator profiles (humanScore ≥ 50) or fail to separate multi-signal slop from clean profiles (slopScore ≤ humanScore + 15).

6. CLI build, audit & sync commands

# 1. Generate an Ed25519 author keypair
./sloptrap rules keygen

# 2. Compile reference specs, sign & encrypt .strule bundles, and write leaderboard.json
./sloptrap rules build-defaults --out ../sloptrap-site --priv <author-private-key-hex>

# 3. Run full cryptographic, WASM section, CPU-bomb & anti-poisoning security audit
./sloptrap rules audit ../sloptrap-site/bundles

# 4. Sync active/all-time installs, GitHub Release downloads & Issue upvotes
./sloptrap rules sync --out ../sloptrap-site

# 5. Check for bundle updates (--anon-rule-rankings=false disables telemetry)
./sloptrap rules check-updates

7. Anti-oracle ranking & Anonymous rule rankings

  • Private holdout & coarse bands: Only truncated SHA-256 commitments appear in leaderboard.json, and Precision/Recall/F1 are published in 0.05 steps with letter bands (S, A, B, C). Holdout F1 gates popularity weight (F1 ≤ 0.50 receives zero popularity multiplier).
  • Anonymous rule rankings (Active & All-Time installs): Clients with opt-in Anonymous rule rankings enabled send a random local 128-bit install_token and active rule IDs during update checks (POST /api/v1/rules/check-updates). The Cloudflare Worker + D1 backend records both cumulative all_time_installs and rolling active_installs over a configurable window (default ACTIVE_WINDOW_DAYS = 30) with per-subnet daily Sybil budgets, and exposes window_days dynamically via GET /api/v1/rules/stats.
