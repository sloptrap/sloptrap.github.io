1. Architecture, Common Syntax & Shared Variables

SlopTrap decouples platform-specific extraction (youtube, tiktok, pinterest, or custom site adapters) from portable, Ed25519-signed WebAssembly 1.0 rule bundles (.strule, format sloptrap-bundle-v2).

  • Common cross-site vocabulary: Readable rules use shared dotted signal names (post.frequency, account.dormancy_days, post.title_reuse, text.formal_prose, voice.pacing_variance, media.synthetic_ratio, link.domain_concentration) mapped cleanly onto the Multi-Site Fingerprint v1 JSON schema.
  • Shared variables & threshold actions: In Rule Studio, rules declare one or more typed WASM f64 locals (var suspicion = 0, var script_risk = 0, var voice_risk = 0), accumulate or set values when conditions match, and evaluate decide threshold blocks into action codes (block, hide, dim, warn, allow).
  • Target-site scoping: Every rule declares target_site (youtube, tiktok, pinterest, or cross-site *) and publishes to its corresponding site leaderboard (/leaderboard/<site>/leaderboard.json).
  • Zero host imports: Any WASM module declaring an Import (2), Table (4), Start (8) or Element (9) section is rejected before it is ever instantiated (see section 6).

2. Trust Tiers (computed from the signing key only)

A rule's tier comes only from the key that signed it. Manifest fields such as provenance, and any verified flag in a feed, carry no trust. verified means tier official and nothing else.

3. Canonical Fingerprint (schema_version 1)

Every producer serializes the rule input through one canonical serializer: all fields, in a fixed order, compact JSON, normalized numbers (no exponents) and sanitized strings. Text conditions match only inside the values of channel.handle, channel.title, channel.description and sample_text, never against key names or numbers. A shortened example of the fields:

4. Guest WebAssembly ABI (wasm-v1)

  • memory (required): exactly one memory, with a declared maximum of at most 32 pages (2 MiB).
  • st_alloc(size: i32) -> i32 (optional): returns where to write the input. Without it, or if it returns 0, the input goes at offset 16384.
  • st_evaluate(ptr: i32, len: i32) -> i64 (required): returns a score 0..100 when the upper 32 bits are 0, or (outPtr << 32) | outLen pointing at at most 4096 bytes of UTF-8 JSON {"score": 0..100 (integral), "confidence"?: (0,1], "reason"?: string ≤ 300}.
  • No other exports. Every evaluation runs in a fresh instance, so no state survives between calls, under a CPU budget (fuel or deadline). A trap, an exhausted budget or bad output is a rule error: that rule is left out of the result and never aborts the others.
  • Ensemble: weight = weight_milli / 1000 × confidence; composite = weighted mean rounded, clamped to 0–100; block ≥ 68, warn ≥ 45.

5. .strule Bundle v2 & Signature

{
  "format": "sloptrap-bundle-v2",
  "manifest": {
    "rule_id": "pinterest-ai-pin-mill",
    "name": "Synthetic Image & SEO Pin Mill",
    "version": "2.0.0",
    "author": "@sloptrap-core",
    "author_public_key": "0540a396ece8ab0f9670a25e03b02e345450a1373b86a7d400dcad79ceec5cc1",
    "target_site": "pinterest",
    "description": "…",
    "repo_url": "https://github.com/sloptrap/sloptrap",
    "interpreter": "wasm-v1",
    "inputs": ["metadata", "upload_cadence", "transcript", "thumbnails"],
    "weight_milli": 1350,
    "overhead": 40,
    "provenance": { "source_repo": "", "source_commit": "", "build_run_url": "", "submission_id": "" }
  },
  "payload_b64": "<base64 of the plain WASM module>",
  "signature_b64": "<64-byte Ed25519 signature>"
}
  • Every manifest field is required and unknown fields are rejected; integers must be JSON integers (weight_milli 1–10000, overhead 1–100); strings are bounded plain text.
  • digest = SHA256("sloptrap-sig-v2\n" ‖ canonical_manifest ‖ "\n" ‖ SHA256(wasm)), signed with pure Ed25519 and verified strictly (RFC 8032). The signature covers every manifest field, including target_site, description, repo_url and provenance.
  • Any verification error rejects the bundle; there is no fallback.
  • No encryption. v1's AES-GCM "encryption" used a key derived from a public seed, so it hid nothing; v2 ships the plain module.
  • Limits: bundle ≤ 512 KiB, WASM ≤ 256 KiB.

6. Automated Audit & CI

Every bundle published on this site is re-checked by scripts/audit_bundles.py on every change and every sync:

  1. Signature & tier: strict v2 verification, tier from the key, the community- id rule, rule id = file name, and the tier each directory allows (bundles/: official; bundles/community/: community).
  2. Static WASM audit: full decode of every function body. Only the type, function, memory, global, export, code, data and datacount sections (plus ignored custom sections); no imports, tables, start or element sections; ≤ 1024 functions, ≤ 64 globals, ≤ 64 data segments; no call_indirect, tail calls, exceptions, reference types, SIMD, atomics, reinterpret ops or unknown opcodes.
  3. Sandboxed execution: wasmtime with a 10,000,000-unit fuel budget, a 32-page memory limit and a fresh instance per call; every output must satisfy the ABI above.

Fixed public probe fingerprints cannot show that a rule is safe (a rule can recognise them), so they are reported for information only and never decide pass or fail. Behavioural acceptance of community rules uses a hidden holdout corpus in the private pipeline.
