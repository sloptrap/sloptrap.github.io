Sandboxed WASM Rules & .strule Specification

SlopTrap decouples its open-source feature extraction and sandbox runtime from pluggable, cryptographically signed, obfuscated WebAssembly detection rules (.strule) that execute deterministically across platforms.

1. Architecture Overview

  • Open-Source Host, Opaque Rule Logic: The host runtime (wazero interpreter mode in Go, or any compliant WebAssembly 1.0 interpreter) is 100% open-source and deterministic, while rule authors distribute compiled, control-flow-flattened WebAssembly bytecode inside encrypted .strule containers.
  • Zero Host Capabilities: Any WASM module containing an Import section (secId == 2, WASI, clocks, sockets, or filesystem imports) is rejected at compile time. Modules are capped at 32 memory pages (2 MiB) and strict execution timeouts / instruction fuel budgets.
  • Input-Driven Cost Optimization: Each rule manifest declares only the input categories it needs (metadata, upload_cadence, transcript, thumbnails, audio_video_stats) and receives a 1..10 overhead score so low-power client devices can pick fast 2/10 rules while servers run deep 8/10 ensembles.

3. Guest WebAssembly ABI (wasm-v1)

Any language targeting standalone WebAssembly 1.0 MVP (Rust wasm32-unknown-unknown, C/Clang, Zig, TinyGo, AssemblyScript, or SlopTrap's built-in RuleSpec compiler) can produce a valid rule module by exporting:

  • memory — Linear memory (1–16 initial pages, max ≤ 32 pages).
  • st_alloc(size: i32) -> i32 (optional) — Returns byte offset where the host writes the UTF-8 ChannelFingerprint JSON (defaults to scratch offset 16384 if omitted).
  • st_evaluate(ptr: i32, len: i32) -> i64 (required) — Evaluates the fingerprint at memory[ptr .. ptr+len] and returns a packed 64-bit integer:
    • Compact return (upper 32 bits == 0): Lower 32 bits hold the integer slop score clamped to 0..100 (confidence defaults to 1.0).
    • Structured JSON return (upper 32 bits > 0): (outPtr << 32) | outLen pointing to UTF-8 JSON {"score": 88, "confidence": 0.92, "reason": "..."} in linear memory.

4. .strule Container & Cryptographic Verification

A .strule file is a portable JSON envelope binding a canonical manifest, an HKDF-AES-256-GCM encrypted WASM payload, and an Ed25519 author signature: 

{
  "format": "sloptrap-bundle-v1",
  "manifest": {
    "rule_id": "necro-hijack-guard",
    "name": "Necro-Hijack & Dormancy Guard",
    "description": "Detects aged/bought YouTube accounts with multi-year dormancy gaps...",
    "version": "1.2.0",
    "author": "@sloptrap-core",
    "author_public_key": "eb85cbf507e27e2c0f94ad723385db3138af32670ea37ca337f0c1866eae02cc",
    "repo_url": "https://github.com/sloptrap/rule-necro-hijack-guard",
    "interpreter": "wasm-v1",
    "inputs": ["metadata", "upload_cadence", "audio_video_stats"],
    "default_weight": 1.25,
    "overhead": 3,
    "encryption": "aes-256-gcm-hkdf"
  },
  "payload_b64": "<12-byte GCM nonce || AES-256-GCM ciphertext || 16-byte tag>",
  "signature_b64": "<64-byte Ed25519 signature>"
}
  • Language-Neutral Canonical Manifest AAD: Compliant runtimes serialize a deterministic newline-delimited canonical byte string used as AES-GCM Additional Authenticated Data (AAD) — tampering with any manifest field (such as lowering overhead or swapping author_public_key) immediately fails authenticated decryption.
  • RFC 5869 HKDF-SHA256 Key Derivation: Derives the 256-bit AES key from the scoring environment seed using salt sloptrap-hkdf-salt-v1 and info sloptrap-bundle-v1|<rule_id>|<author_pub_hex>|<version>.
  • Ed25519 Author Provenance: Verified over SHA-256("sloptrap-sig-v1:" || canonicalManifest || 0x00 || rawWasmBytes).

5. CLI Keygen, Build & Verification

# 1. Generate an Ed25519 author keypair
./sloptrap rules keygen

# 2. Compile reference specs (with state-machine control-flow flattening),
#    sign & encrypt .strule bundles, evaluate on holdout corpus, and write leaderboard.json
./sloptrap rules build-defaults --out ../sloptrap-site --priv <author-private-key-hex>

# 3. Sync live active installs, GitHub Release downloads & Issue 👍 likes
./sloptrap rules sync --out ../sloptrap-site

# 4. Check for bundle updates (pass --anon-rule-rankings=false to disable anonymous heartbeat)
./sloptrap rules check-updates

# 5. Upvote a rule on the leaderboard via gh CLI
./sloptrap rules like necro-hijack-guard

# 6. Verify Ed25519 signature & decrypt payload of any .strule bundle
./sloptrap rules verify ../sloptrap-site/bundles/necro-hijack-guard.strule

6. Anti-Oracle Leaderboard & Anonymous Rule Rankings

  • Private Holdout Corpus: Only truncated SHA-256 channel commitments appear publicly in leaderboard.json; raw channel handles and IDs remain private.
  • Holdout Perturbation & Rate Limiting: Periodic holdout subset rotation (perturbSeed) and per-author Ed25519 submission rate limits (leaderboard.RateLimiter) prevent iterative threshold probing.
  • Coarse Banding & Accuracy Quality Gate: Published Precision, Recall, and F1 are rounded to 0.05 increments alongside coarse letter bands (S ≥ 0.90, A ≥ 0.78, B ≥ 0.60, C < 0.60). Holdout F1 acts as a multiplicative gate (F1 ≤ 0.50 receives zero popularity boost) so botted downloads or likes cannot elevate permissive rules.
  • Anonymous Rule Rankings (Active Installs): Clients with Anonymous rule rankings enabled send a random local 128-bit install_token (never tied to a YouTube account or device serial) and their enabled rule IDs during periodic update checks (POST /api/v1/rules/check-updates), maintaining a rolling 14-day active-install count with per-subnet daily Sybil caps. Disabling Anonymous rule rankings switches update checks to plain static leaderboard.json fetches.
  • GitHub Release Downloads & Issue 👍 Likes: Distributable .strule assets are published on GitHub Releases for native download counting, and each rule has a dedicated leaderboard-rule GitHub Issue where users react with 👍 (one vote per GitHub account).
