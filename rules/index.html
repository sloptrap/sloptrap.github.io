WASM Rule Engine & .strule Specification

SlopTrap decouples platform-specific extraction (`youtube`, `tiktok`, `pinterest`, or custom site adapters) from portable, cryptographically signed WebAssembly 1.0 rule bundles (.strule).

1. Architecture overview

  • Target-site scoping: Every rule declares target_site (e.g. "youtube", "tiktok", "pinterest", or "*" for universal cross-platform rules) and is published to its corresponding site leaderboard (/leaderboard/<site>/leaderboard.json).
  • Zero host imports: Any WASM binary declaring an Import section (secId == 2), Custom section (secId == 0), or implicit Start section (secId == 8) is rejected before execution.
  • Bounded memory & fuel: Linear memory must declare an explicit maximum of ≤ 32 pages (2 MiB), and calls run under strict instruction fuel / deadline budgets.

2. Verified rule provenance tiers

Integrating applications and end users can set VerifiedOnly: true to restrict execution exclusively to Verified rules. A bundle qualifies as Verified through one of two audited paths:

Tier Requirements & Verification
Verified · Official Defined by SlopTrap maintainers and cryptographically signed by a public key in OfficialMaintainerKeys. Spoofing tier: "official" with any non-maintainer Ed25519 key fails CI and runtime verification.
Verified · Source Submitted by a community author who has granted read access to the rule's source repository and pinned the build to an immutable 40-character git source_commit SHA and specific GitHub Actions build_run_url producing the exact bundle_sha256.
Community Signed with the author's Ed25519 key and passing all automated WASM capability, fuel-limit, and anti-poisoning security checks, without source-build attestation (skipped when VerifiedOnly is enabled).

4. Guest WebAssembly ABI (wasm-v1)

  • memory — Bounded linear memory (max ≤ 32 pages).
  • st_alloc(size: i32) -> i32 (optional) — Returns byte offset for the UTF-8 JSON input slice.
  • st_evaluate(ptr: i32, len: i32) -> i64 (required) — Returns integer score 0..100 in the lower 32 bits when upper 32 bits are 0, or (outPtr << 32) | outLen pointing to {"score": 88, "confidence": 0.92, "reason": "..."}.

6. Automated malicious-content audit & CI

Every pull request or push modifying .strule files or any site leaderboard runs validate-rules.yml (and locally via ./sloptrap rules audit):

  1. Cryptographic & provenance check: Verifies Ed25519 signatures, HKDF-AES-256-GCM manifest AAD, SHA-256 parity across leaderboard/*/leaderboard.json, and prevents unverified keys from claiming official or unattested verified status.
  2. Binary section firewall: Rejects WASM Custom (0), Import (2), and Start (8) sections, unbounded or > 32-page memory, and non-whitelisted exports.
  3. Fuel-metered sandbox & anti-poisoning: Traps CPU bombs via instruction fuel limits, verifies determinism, and rejects rules that score clean human profiles ≥ 50 or fail to separate slop from human baselines.
