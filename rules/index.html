1. Architecture, Common Syntax & Shared Variables

SlopTrap decouples platform-specific extraction (youtube, tiktok, pinterest, or custom site adapters) from portable, cryptographically signed WebAssembly 1.0 rule bundles (.strule).

  • Common cross-site vocabulary: Readable rules use shared dotted signal names (post.frequency, account.dormancy_days, post.title_reuse, text.formal_prose, voice.pacing_variance, media.synthetic_ratio, link.domain_concentration) mapped cleanly onto the Multi-Site Fingerprint v1 JSON schema.
  • Shared variables & threshold actions: In Rule Studio, rules declare one or more typed WASM f64 locals (var suspicion = 0, var script_risk = 0, var voice_risk = 0), accumulate or set values when conditions match, and evaluate decide threshold blocks into action codes (block, hide, dim, warn, allow).
  • Target-site scoping: Every rule declares target_site (or cross-site all) and publishes to its corresponding site leaderboard (/leaderboard/<site>/leaderboard.json).
  • Zero host imports: Any WASM binary declaring an Import (2), Custom (0), or Start (8) section is rejected prior to execution.

2. Verified Rule Provenance Tiers

Integrators and users can enable VerifiedOnly to execute exclusively Verified rules:

Tier Verification Criteria
Verified · Official Defined by SlopTrap maintainers and signed by a public key in OfficialMaintainerKeys.
Verified · Source Submitted by an author who granted repository read access and pinned the artifact to an immutable 40-char git source_commit SHA and GitHub Actions build_run_url.
Community Ed25519-signed and passing automated WASM capability, fuel-limit, and anti-poisoning checks without source-build attestation.

4. Guest WebAssembly ABI (wasm-v1)

  • memory — Bounded linear memory (max ≤ 32 pages / 2 MiB).
  • st_alloc(size: i32) -> i32 (optional) — Returns scratch offset for UTF-8 JSON input bytes.
  • st_evaluate(ptr: i32, len: i32) -> i64 (required) — Returns integer score 0..100 in the lower 32 bits when upper 32 bits are 0, or (outPtr << 32) | outLen for structured JSON output.

6. Automated Malicious-Content Audit & CI

  1. Cryptographic & provenance check: Verifies Ed25519 signatures, HKDF-AES-256-GCM manifest AAD, SHA-256 parity across leaderboard/*/leaderboard.json, and blocks spoofed official or unattested verified claims.
  2. Binary section firewall: Rejects WASM Custom (0), Import (2), and Start (8) sections, unbounded or > 32-page memory, and non-whitelisted exports.
  3. Fuel-metered sandbox & anti-poisoning: Traps CPU bombs via instruction fuel limits, verifies determinism, and rejects rules scoring clean human profiles ≥ 50.
